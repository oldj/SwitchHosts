# macOS 托盘回归验证

本文用于验证 PR [#1051](https://github.com/oldj/SwitchHosts/pull/1051) 及后续托盘窗口改动。
排查历史见 [macOS 托盘全屏问题](macos-tray-fullscreen-bug.md)。以下命令均从仓库根目录运行。

## macOS 27 点击事件兼容性

`tray-icon 0.24.2` 在 macOS 27 上给 `NSStatusItem` 常驻绑定菜单时，左键事件会被系统
截走，`show_menu_on_left_click(false)` 也无法让事件到达应用。因此普通桌面和全屏中
点击图标都可能无法弹出 Hosts 列表小窗；直接调用窗口显示函数的生命周期测试仍会通过。
上游修复见 [tray-icon #365](https://github.com/tauri-apps/tray-icon/pull/365)。

项目要求 Tauri 至少为 2.12.1，锁定的 `tray-icon 0.25.1` 包含该修复：只在需要弹出菜单
时临时绑定原生菜单，关闭后解除绑定。验证时除下方窗口矩阵外，还应在 macOS 27 上检查：

- 左键图标显示 Hosts 列表小窗，右键图标显示菜单。
- 关闭右键菜单后，左键仍能打开小窗。
- 更改语言或 Dock 图标设置触发菜单重建后，左键仍能打开小窗。

## 自动化测试

普通 Rust 测试（不启动原生窗口）：

```sh
cargo test --locked --manifest-path src-tauri/Cargo.toml
```

`tray::tests::dismiss_monitor_accepts_only_mouse_button_presses` 检查全部 64 个事件掩码位：
只允许左键、右键和其他鼠标键按下，排除移动、拖动、抬起、滚轮及键盘事件。
结构测试检查两个监听器使用被测试的掩码，生产入口调用被测试的窗口模块；另外检查托盘显示
入口及原生显示函数不重新引入全局激活调用。Windows/Linux 所需的 `set_focus()` 不受此限制。

原生生命周期测试需要 **macOS 已登录的桌面会话**，会短暂显示空白测试窗口：

```sh
cargo test --locked --manifest-path src-tauri/Cargo.toml --features native-tray-tests --test macos_tray_lifecycle
```

该测试直接编译生产模块 `src-tauri/src/tray/window.rs`，不复制窗口实现。
主窗口场景还通过仅在 `native-tray-tests` 特性下提供的接口调用生产显示门控和菜单分发。
独立测试应用使用单独的应用标识与内嵌静态页面，不启动 SwitchHosts
存储、菜单、提权辅助程序或 hosts 写入，也不依赖 Vite 开发服务器。

测试连续运行十轮：前五轮只存在托盘窗口，后五轮保留另一个隐藏的主窗口。每轮检查：

- 新窗口隐藏，Tauri 宿主保留原生窗口类型，独立面板承载 WebView，具有非激活样式、跨 Space 和全屏辅助行为。
- 实际窗口层级为 `PopUpMenu`（101），可成为 key window、不可成为 main window。
- 保持系统鼠标不动，按各已连接显示器的点击事件坐标轮流打开面板，检查靠边定位及图标坐标无效时的回退。
- 重复显示后，面板仍可见、键盘焦点在 WebView 内，且两次显示使用同一个原生 NSPanel。
- 关闭时归还原 WebView 内容，解绑面板，并可正常移除关闭前注册的窗口观察者；随后实际收到 `Destroyed` 事件，Tauri 窗口注册消失。
- 完成销毁后才开始下一轮，同一标签可再次创建，另一个主窗口不会随托盘关闭。
- 隐藏主窗口在已连接显示器之间移动时保持尺寸；同屏再次唤起保持位置；菜单栏/Dock 导致工作区变化时仍能找到目标屏幕。
- 至少两块显示器时，另建带旧屏幕位置的隐藏窗口，等框架处理异步位置恢复后发送 renderer ready，直接验证生产显示门控将首次显示放到目标屏幕。单屏环境明确跳过跨屏断言，但仍检查显示门控。

随后在 `tests/macos_tray_lifecycle/main_window_cases.rs` 中检查：

- renderer ready 重复通知和超时回退不会重新打开已隐藏的窗口。
- 等待重建期间采用最后一次明确的屏幕请求；不带目标屏幕的请求不抹掉它。
- 被取消的旧门控在 ready 和超时回调后均保持隐藏；没有 ready 时，5 秒回退仍在目标屏幕显示。
- 最小化主窗口恢复到目标屏幕，普通无目标的显示请求保留原位置。
- 右键菜单使用打开时记录的屏幕，而不是选择菜单项时鼠标所在的屏幕。此用例不移动真实鼠标，选择另一块屏幕作为已记录目标来验证生产菜单分发。

测试有 30 秒运行超时，卡住或断言失败返回非零状态；这不包括 Cargo 编译耗时。
它不能证明所有原生对象都无泄漏，也不模拟真实鼠标点击、另一个应用的全屏 Space 或键盘焦点恢复。
尤其不能把隔离测试应用启动时 Tauri 自身的激活当作托盘点击的激活行为；这些场景见下方手工清单。

需要排查原生对象释放错误时，可额外运行：

```sh
NSZombieEnabled=YES cargo test --locked --manifest-path src-tauri/Cargo.toml --features native-tray-tests --test macos_tray_lifecycle
```

检查输出是否出现 `message sent to deallocated instance`。Zombie 模式可能改变释放行为，
因此它仅用于辅助诊断，不能替代不开启该选项的正常测试。

## CI

`.github/workflows/ci.yml` 对目标为 `master`、`develop` 的 PR，以及这两个分支的 push 执行检查。
Linux 保留现有完整测试；新增 `rust-macos` job 运行 Rust 测试和原生生命周期测试。
原生测试先独立编译，再在两分钟的步骤超时内运行，避免编译耗时挤占窗口测试时间。
自托管或无桌面的环境应先配置桌面会话，不应把跳过原生测试报告为通过。

```sh
actionlint .github/workflows/ci.yml
```

## 手工回归矩阵

开启托盘小窗功能。使用可回滚的测试 hosts 配置，记录原启用项并在验证结束后恢复。
“主窗口关闭”一列应启用轻量模式并关闭主窗口，确认进程仍驻留；不是退出应用。

| 场景 | 当前 Space | Dock 图标 | 主窗口 | 显示器 |
| --- | --- | --- | --- | --- |
| 1 | 普通桌面 | 显示 | 打开 | 单屏 |
| 2 | 普通桌面 | 隐藏 | 打开 | 单屏 |
| 3 | 普通桌面 | 显示 | 轻量模式关闭 | 单屏 |
| 4 | 普通桌面 | 隐藏 | 轻量模式关闭 | 单屏 |
| 5 | 其他应用全屏 | 显示 | 打开 | 单屏 |
| 6 | 其他应用全屏 | 隐藏 | 打开 | 单屏 |
| 7 | 其他应用全屏 | 显示 | 轻量模式关闭 | 单屏 |
| 8 | 其他应用全屏 | 隐藏 | 轻量模式关闭 | 单屏 |

多显示器时，在副屏托盘上重复场景 1、5、7；尽量覆盖不同缩放比例。记录 macOS 的
“显示器具有单独的空间”设置，确认弹窗位于被点击的显示器且没有越过工作区边界。
没有对应设备的场景标记为“未执行”，不要推断为通过。

每个场景执行下列步骤，记录失败步骤及录屏或日志：

1. 将另一个应用置于前台（全屏场景使用独立的全屏 Space），点击托盘图标。
   小窗应出现在当前 Space，不切回桌面，不带出 SwitchHosts 主窗口。
2. 在小窗内移动鼠标，再移出但不点击；小窗都应保持显示。
3. 第一次点击一个 hosts 开关，应立即响应；再次切换、滚动列表应可用。
   核对实际应用结果，而非仅看开关动画。
4. 分别测试左键、右键、鼠标中键或其他按键点击外部；均应关闭小窗。
   外部应用应正常接收点击，不需要多点一次才能操作。
5. 打开后再次点击托盘图标；应关闭且不立即重开。稍后再点可以重新打开。
   连续执行至少十轮，观察空白残窗、崩溃和不能再打开的问题。
6. 点击小窗的“显示主窗口”按钮；主窗口正常显示，之后仍能开关托盘小窗。
7. 关闭小窗后在原应用的文本输入区输入，确认键盘焦点正常。
   再单独观察 Cmd-Tab、切换 Space 后的表现，异常时记录实际行为。
8. 轻量模式场景确认关闭小窗没有退出驻留进程，仍可通过托盘重建主窗口。

## 多显示器主窗口定位（#941）

此项需分别检查托盘小窗和主窗口，不能仅以小窗定位正确判为通过。使用隔离配置，
将主窗口留在 A 屏后关闭，在 B 屏点击托盘：

1. 开启托盘小窗，检查小窗在 B 屏；点击“显示主窗口”、双击方案，检查主窗口及添加/编辑弹层也在 B 屏。
2. 关闭托盘小窗，点击 B 屏图标直接打开主窗口；右键菜单的“显示主窗口”同样检查；另测打开菜单后把鼠标移到另一屏，再用键盘选择“显示主窗口”，窗口仍应出现在打开菜单的屏幕。
3. 分别在轻量模式关闭/开启时重复。开启时必须确认旧窗口已经销毁，再点击另一个屏幕的图标；观察首次显示，不能只检查创建后、显示前的隐藏窗口坐标。
4. 主窗口已在目标屏幕时，确认再次唤起保持用户位置和尺寸；普通启动仍使用记忆的位置。
5. 包含上方或左侧的副屏，检查负坐标及窗口大于目标工作区的情况。全屏主窗口保留其原有 Space，不强行跨屏搬移。

Tauri 构建窗口时会排队恢复位置，过早调用原生定位可能被覆盖。因此重建路径需要在
renderer ready（或超时回退）的最终显示步骤应用目标位置，并让等待期间的新托盘请求更新目标。
