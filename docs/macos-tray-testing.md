# macOS 托盘回归验证

本文用于验证 PR [#1051](https://github.com/oldj/SwitchHosts/pull/1051) 及后续托盘窗口改动。
排查历史见 [macOS 托盘全屏问题](macos-tray-fullscreen-bug.md)。以下命令均从仓库根目录运行。

## 自动化测试

普通 Rust 测试（不启动原生窗口）：

```sh
cargo test --locked --manifest-path src-tauri/Cargo.toml
```

`tray::tests::dismiss_monitor_accepts_only_mouse_button_presses` 检查全部 64 个事件掩码位：
只允许左键、右键和其他鼠标键按下，排除移动、拖动、抬起、滚轮及键盘事件。
结构测试仅保留接线检查，确保两个监听器使用被测试的掩码，生产入口调用被测试的窗口模块。

原生生命周期测试需要 **macOS 已登录的桌面会话**，会短暂显示空白测试窗口：

```sh
cargo test --locked --manifest-path src-tauri/Cargo.toml --features native-tray-tests --test macos_tray_lifecycle
```

该测试直接编译生产模块 `src-tauri/src/tray/window.rs`，不复制窗口实现。
独立测试应用只注册 NSPanel 插件，使用单独的应用标识与内嵌静态页面，不启动 SwitchHosts
存储、菜单、提权辅助程序或 hosts 写入，也不依赖 Vite 开发服务器。

测试连续运行十轮：前五轮只存在托盘窗口，后五轮保留另一个隐藏的主窗口。每轮检查：

- 新窗口隐藏、面板已注册，具有非激活样式、跨 Space 和全屏辅助行为。
- 实际窗口层级为 `PopUpMenu`（101），可成为 key window、不可成为 main window。
- 显示后窗口可见，重复显示复用同一个原生窗口。
- 关闭立即清除面板注册、恢复 NSWindow 类型；随后实际收到 `Destroyed` 事件，Tauri 窗口注册消失。
- 完成销毁后才开始下一轮，同一标签可再次创建，另一个主窗口不会随托盘关闭。

测试有 30 秒运行超时，卡住或断言失败返回非零状态；这不包括 Cargo 编译耗时。
它不能证明所有原生对象都无泄漏，也不模拟真实鼠标点击、另一个应用的全屏 Space 或键盘焦点恢复。
尤其不能把隔离测试应用启动时 Tauri 自身的激活当作托盘点击的激活行为；这些场景见下方手工清单。

需要排查原生对象释放错误时，可额外运行：

```sh
NSZombieEnabled=YES cargo test --locked --manifest-path src-tauri/Cargo.toml --features native-tray-tests --test macos_tray_lifecycle
```

检查输出是否出现 `message sent to deallocated instance`。Zombie 模式可能改变释放行为，
因此它仅用于辅助诊断，不能替代不开启该选项的正常测试。

## CI

`.github/workflows/ci.yml` 对目标为 `master`、`develop` 的 PR，以及这两个分支的 push 执行检查。
Linux 保留现有完整测试；新增 `rust-macos` job 运行 Rust 测试和原生生命周期测试。
原生测试先独立编译，再在两分钟的步骤超时内运行，避免编译耗时挤占窗口测试时间。
自托管或无桌面的环境应先配置桌面会话，不应把跳过原生测试报告为通过。

```sh
actionlint .github/workflows/ci.yml
```

## 手工回归矩阵

开启托盘小窗功能。使用可回滚的测试 hosts 配置，记录原启用项并在验证结束后恢复。
“主窗口关闭”一列应启用轻量模式并关闭主窗口，确认进程仍驻留；不是退出应用。

| 场景 | 当前 Space | Dock 图标 | 主窗口 | 显示器 |
| --- | --- | --- | --- | --- |
| 1 | 普通桌面 | 显示 | 打开 | 单屏 |
| 2 | 普通桌面 | 隐藏 | 打开 | 单屏 |
| 3 | 普通桌面 | 显示 | 轻量模式关闭 | 单屏 |
| 4 | 普通桌面 | 隐藏 | 轻量模式关闭 | 单屏 |
| 5 | 其他应用全屏 | 显示 | 打开 | 单屏 |
| 6 | 其他应用全屏 | 隐藏 | 打开 | 单屏 |
| 7 | 其他应用全屏 | 显示 | 轻量模式关闭 | 单屏 |
| 8 | 其他应用全屏 | 隐藏 | 轻量模式关闭 | 单屏 |

多显示器时，在副屏托盘上重复场景 1、5、7；尽量覆盖不同缩放比例。记录 macOS 的
“显示器具有单独的空间”设置，确认弹窗位于被点击的显示器且没有越过工作区边界。
没有对应设备的场景标记为“未执行”，不要推断为通过。

每个场景执行下列步骤，记录失败步骤及录屏或日志：

1. 将另一个应用置于前台（全屏场景使用独立的全屏 Space），点击托盘图标。
   小窗应出现在当前 Space，不切回桌面，不带出 SwitchHosts 主窗口。
2. 在小窗内移动鼠标，再移出但不点击；小窗都应保持显示。
3. 第一次点击一个 hosts 开关，应立即响应；再次切换、滚动列表应可用。
   核对实际应用结果，而非仅看开关动画。
4. 分别测试左键、右键、鼠标中键或其他按键点击外部；均应关闭小窗。
   外部应用应正常接收点击，不需要多点一次才能操作。
5. 打开后再次点击托盘图标；应关闭且不立即重开。稍后再点可以重新打开。
   连续执行至少十轮，观察空白残窗、崩溃和不能再打开的问题。
6. 点击小窗的“显示主窗口”按钮；主窗口正常显示，之后仍能开关托盘小窗。
7. 关闭小窗后在原应用的文本输入区输入，确认键盘焦点正常。
   再单独观察 Cmd-Tab、切换 Space 后的表现，异常时记录实际行为。
8. 轻量模式场景确认关闭小窗没有退出驻留进程，仍可通过托盘重建主窗口。
